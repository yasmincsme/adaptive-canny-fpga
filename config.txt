# Como rodar os testes de detecção de bordas

Artefatos gerados (entrada_canny.hex, saida_canny.hex, saida_canny.png,
image_params.vh, binários de simulação) ficam todos em build/ -- não
suba esses arquivos manualmente, eles são regenerados a cada rodada.

## Caminho rápido: script único (iverilog)

  python3 scripts/run_batch_edge_tests.py

Roda o pipeline completo para todas as imagens em images/, gerando
images/results/<nome>_edges.png para cada uma. Por padrão redimensiona
para 512x512 (resolução alvo do projeto).

Atenção: este simulador processa ~1 pixel a cada ~52 ciclos. Medido na
prática: uma imagem 512x512 leva ~26 minutos. Para iterar rápido:

  python3 scripts/run_batch_edge_tests.py --width 128 --height 128

## Passo a passo manual

### 1. (Opcional) Converta uma imagem real para o formato de entrada
tb_canny_top_module.v lê a imagem de build/entrada_canny.hex (pixel RGB de
24 bits por linha) e as dimensões de build/image_params.vh. Ambos já vêm
com um quadrado sintético 32x32 de fábrica -- só rode este passo se quiser
testar com uma imagem sua:

  python3 scripts/png_to_hex.py caminho/para/imagem.png

Por padrão a imagem é redimensionada para 512x512. Use --width/--height
para outro tamanho, ou --no_resize para manter o tamanho original. A
imagem pode ser colorida -- a conversão para escala de cinza acontece
dentro do datapath (rgb_gray_average.v), o script não faz isso.

### 2. Compile e rode

Com iverilog (lista de arquivos dedicada ao teste de borda, independente
do filelist.f principal usado para outros testbenches do projeto):

  iverilog -g2012 -I build -o build/sim_canny_top.vvp $(grep -v '^//' filelist_canny_top.f)
  vvp build/sim_canny_top.vvp

Com o Cadence Xcelium (filelist.f principal -- lembre de deixar só
src/Canny_top/tb_canny_top_module.v descomentado nele):

  xrun -incdir build -f filelist.f

Para abrir o SimVision (GUI de formas de onda):

  xrun -incdir build -access +rwc -gui -f filelist.f

A flag -incdir build é necessária porque a testbench usa
`include "image_params.vh"`, que fica em build/.

### 3. Veja o resultado
A simulação grava build/saida_canny.hex (um píxel de borda por linha,
%02X). Para reconstruir como PNG:

  python3 scripts/hex_to_png.py

Gera build/saida_canny.png (por padrão), lendo as dimensões de saída a
partir de build/image_params.vh (já ajustadas pela perda de borda do
pipeline: -6 de largura, -5 de altura).

## Síntese com Genus (Cadence)

Scripts em synth/scripts/, ainda não executados neste ambiente -- faltam
duas coisas antes de rodar de verdade:

1. **Biblioteca de células padrão (.lib)**: ainda não escolhemos uma
   PDK para o projeto. Preencha LIB_DIR e TARGET_LIBS em
   synth/scripts/setup.tcl antes de tentar sintetizar -- o script aborta
   com um erro claro se esquecer.
2. **Conferir a sintaxe Genus** em run_synth.tcl contra a versão
   instalada (foi escrito com base na sintaxe típica de
   read_hdl/elaborate/syn_generic/syn_map/syn_opt + redirect para
   relatórios, mas não foi testado neste ambiente).

Depois de preencher setup.tcl, a partir de synth/scripts/:

  genus -legacy_ui -files run_synth.tcl -log ../logs/run_synth

O que os scripts fazem:

- filelist_synth.f (raiz do repo): mesma lista de filelist_canny_top.f,
  mas sem a testbench -- é o que run_synth.tcl lê.
- synth/scripts/setup.tcl: caminhos da biblioteca de células + diretórios
  de saída (synth/outputs/, synth/reports/).
- synth/scripts/constraints.sdc: clock de 10 ns (100 MHz) como ponto de
  partida neutro, reset assíncrono como false path, I/O delays em 40% do
  período. Ajuste depois de ver o report_timing.rpt -- não precisa
  acertar de primeira. Como referência de ordem de grandeza (não uma meta
  a bater): o artigo Kalbasi & Nikmehr (IEEE Access 2020) reporta 263 MHz
  num Virtex-V e 355 MHz num Virtex-7 para o design deles.
- synth/scripts/run_synth.tcl: lê o RTL, elabora canny_top_module, aplica
  as constraints, roda syn_generic/syn_map/syn_opt, e escreve relatórios
  (área, timing, potência, gates) em synth/reports/ e netlist/SDC/db em
  synth/outputs/.

Ponto de atenção já sinalizado no script: config_table.v carrega
config_table.mem via $readmemh numa ROM (`reg [33:0] rom [0:55]`) --
confirme no log de elaboração que o Genus está sintetizando isso como
lógica combinacional (mux tree), não pedindo um macro de memória que não
temos.
